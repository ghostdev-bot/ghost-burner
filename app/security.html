What Ghost Burner can do with your wallet.
And what it can't.

Ghost Burner is a website that builds Solana transactions in your browser and asks your wallet to sign them. There is no server holding your keys and no custom smart contract. This page lists exactly what goes into each transaction, so you can check it against what your wallet shows you.

  • No seed phrase, ever. Ghost Burner never asks for your seed phrase or private key. If any page does, it is a scam.
  • No token approvals. It never asks for an approval, a delegate or any authority over your tokens.
  • Only what you select. It closes or burns only the accounts you ticked on the review screen.
  • Simulated before you sign. Every transaction is run as a simulation first, and the app checks every instruction in it.

What Ghost Burner does

  • Reads your public token accounts from the Solana chain (no signature needed).
  • Closes empty token accounts you select, refunding their rent to your wallet.
  • Burns tokens or standard NFTs only if you tick them yourself, then closes the account and refunds the rent to you.
  • Charges 2% of the SOL rent you get back, as plain SOL transfers inside the same transaction.

What it doesn't do

  • No custody. It never holds your SOL, tokens or keys, and there is no backend server.
  • No transfers of your tokens. Tokens are never sent to anyone. They are burned (destroyed) or left alone.
  • No approvals or authority changes. No Approve, no delegate, no SetAuthority, no change of owner.
  • No fee on token value. The fee is taken only from rent you reclaim, never from your tokens.

Exactly what a transaction contains

Each transaction has you as the only signer and fee payer, and only these instructions:

Compute Budget: set compute unit limit and priceSolana network fee settings
SPL Token or Token-2022: CloseAccountcloses an account you selected, rent goes to you
SPL Token or Token-2022: BurnCheckedonly for tokens you ticked; burns that account's balance
Metaplex Token Metadata: Burn (V1)only for standard NFTs you ticked; rent goes to you
System Program: Transferthe fee, from your wallet to the fee wallets below

Programs: Token TokenkegQ…VQ5DA · Token-2022 TokenzQd…PxuEb · Token Metadata metaqbxx…18x1s · System 1111…1111 · Compute Budget ComputeBudget1…

Before the review screen appears, the app checks every instruction against this list and stops if it finds anything else, if a token instruction touches an account you didn't select, or if a fee transfer is larger than shown. After your wallet signs, it checks again that nothing was added before sending. You can compare all of this with the instructions your wallet lists, and with the transaction on an explorer afterwards.

The fee is 2% of the SOL rent you reclaim, rounded down, and never more: the code refuses to load a configuration above a hard cap, and checks each fee transfer against its percentage before you sign.

Tips for staying safe

  • Read the Phantom (or other wallet) popup before approving. It should show SOL coming back to you, small SOL transfers to the fee wallets above, and the tokens you chose to burn. Nothing else.
  • Use a wallet that holds only what you'll burn. Move valuable tokens and NFTs to another wallet first, then connect the one with the junk.
  • Check the address bar. The real site is ghostburner.surge.sh. Copies can look identical.
  • Never type a seed phrase into any website, including this one.

Free scans, run daily

Last scanned: Nov 5, 2026 (US Eastern)

  • npm audit (libraries shipped in the site): 5 known advisories (1 high, 4 moderate) in bigint-buffer, stream-json, uuid.
  • OSV-Scanner (every package in the lockfile, including build tools): 14 advisories (3 high, 10 medium, 1 low) in bigint-buffer, esbuild, stream-json, uuid, vite.
  • Semgrep (JavaScript, security-audit, secrets and XSS rule packs): 0 findings in 19 source files.
  • gitleaks (leaked keys or passwords in the public code and its history): 0 leaks found.
  • Live site check: files served match our build: yes. Only fee wallets in the code are the two above: yes. Content-Security-Policy set in each page: yes. Extra security headers sent by the host: not available on our free host (Surge), so the page uses meta tags and a frame-busting guard instead.
  • Manual review of the transaction-building code (Nov 4, 2026): it only emits the instructions listed above, only for accounts you select, with the fee capped and checked; no approvals, authority changes or token transfers.

Our read of the library advisories: they all come through Solana's official JavaScript libraries (@solana/web3.js 1.x and @solana/spl-token) or the Vite build tool, and fixing them needs a major upgrade of those libraries that hasn't been done yet. The Vite/esbuild ones affect the developer's build machine, not the site you load. In the browser, bigint-buffer runs its plain-JavaScript version, the uuid issue is in functions the site doesn't use, and stream-json isn't included in the site at all.

These are free automated tools plus our own code review. They catch known problems; they can't prove the code is bug-free, and they are not a substitute for a professional audit.
